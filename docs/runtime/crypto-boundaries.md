# Crypto And Low-Level Boundary Audit

This document closes the Milestone 8 audit requirements for project-owned cryptographic code and intentional low-level C/C++ interoperation.
It applies to the repository state reviewed on 2026-07-25.

## Primitive Facade Audit

`wg-sysmodule/src/wireguard/crypto/primitives.cpp` is the sole production bridge to the crypto backends.
Its public interface is in `primitives.hpp`.
Protocol and runtime code must not include `monocypher.h` or the vendored BLAKE2 header.

`primitives.cpp` was reviewed against all direct production includes and calls listed above.
The test suite has a separate direct-backend conformance case in `test/host/crypto_primitive_tests.cpp`; it is compiled only by host test targets, not the sysmodule.
That suite uses RFC 7693, RFC 8439, the official BLAKE2 KAT corpus, and an RFC 7748 X25519 vector.
The test-only C calls and pointer conversion are intentional so backend conformance is independently observable without expanding the production façade.

## Intentional Low-Level Boundaries

The project does not treat raw C APIs as a style goal.
The following retained uses are necessary boundaries.
New uses must belong to one of these categories, preserve the listed invariant, and be documented here or adjacent to the code.

| Boundary                         | Files reviewed                                                                                                                                                                                                                                                                                                                              | Intentional operations and invariant                                                                                                                                                                                                                                                                                                                                              |
|----------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Vendored third-party C           | `wireguard/crypto/monocypher.*`, `wireguard/crypto/third_party/blake2/*`                                                                                                                                                                                                                                                                    | Kept unmodified for upstream reviewability. Provenance is recorded in the adjacent `UPSTREAM.md` files; project code cannot call them outside `primitives.cpp` or the host-only conformance test.                                                                                                                                                                                 |
| Crypto opaque storage            | `wireguard/crypto/primitives.cpp`                                                                                                                                                                                                                                                                                                           | `reinterpret_cast`, placement construction, and byte clearing are needed because the BLAKE2 C state is intentionally hidden from the C++ public API. Storage size/alignment assertions, lifecycle flags, and immediate clearing constrain the boundary.                                                                                                                           |
| libnx allocator ABI              | `libnx_alloc_hooks.cpp`                                                                                                                                                                                                                                                                                                                     | `malloc`, `free`, pointer alignment, and header recovery implement libnx allocation hooks. The allocation header records the original base and valid alignment; no protocol data crosses this boundary.                                                                                                                                                                           |
| Horizon ABI wrappers             | `platform/horizon/{sync,work,udp,endpoint_resolution,network_path_service}.cpp`                                                                                                                                                                                                                                                             | Placement construction, laundering, address-family casts, and byte copies bridge opaque C storage and `sockaddr`/NIFM/libnx structures. Every conversion is guarded by the declared ABI object size, address family, or initialized storage lifetime.                                                                                                                             |
| Fixed packet and wire data       | `runtime/packet_data_plane.cpp`, `runtime/debug_probe_runner.cpp`, `wireguard/{debug_probe,session}.cpp`, `platform/endpoint_parser.cpp`                                                                                                                                                                                                    | `memcpy` performs fixed-size byte transfer into bounded packet, address, cookie, and endpoint arrays. | Explicit object reset            | `wireguard/{device,peer}.cpp`, `runtime/{daemon_runtime,peer_configuration}.cpp`                                                                                                                                                                                                                                                            | `destroy_at`/`construct_at` replace aggregate assignment where reset must retire protocol state and rebuild a known value-initialized object without large transient stack frames.                                                                                                                                                                                                |
| C-string platform contracts      | `config_loader.cpp`, `fs_runtime.cpp`, `ipc_service.cpp`, `logger.cpp`, `runtime/{daemon_runtime,peer_configuration,udp_binding,encrypted_receive_pump}.cpp`, `runtime/autostart_persistence.hpp`, `runtime/peer/{activation,lifecycle}.cpp`, `platform/{endpoint_parser.cpp,horizon/endpoint_resolution.cpp}`, `wireguard/debug_probe.cpp` | `snprintf`, `strncpy`, `strncmp`, `strtoul`, `strchr`, bounded copies, and fixed character arrays are retained for Horizon IPC, filesystem, logging, persisted config, resolver, and protocol text C APIs. | Protocol labels                  | `wireguard/handshake.cpp`                                                                                                                                                                                                                                                                                                                   | A single `char[]` to byte-span conversion represents ASCII Noise labels. They supply C ABI fixtures, deterministic packet construction, or fuzz entry points and are never linked into the sysmodule.                                                                                                                                                                                           |

No unclassified raw-memory, C-string, or C ABI use remains in project-owned target code.

## Review Maintenance

When adding a crypto operation, update the primitive table with its backend, production call sites, failure behavior, and vector source.
When adding a raw pointer, C string, placement-storage, or byte-copy operation outside a vendored directory, first prefer a typed C++ alternative.
If an ABI boundary remains necessary, add its file and invariant to this document and keep the operation adjacent to the boundary rather than propagating it into protocol code.
